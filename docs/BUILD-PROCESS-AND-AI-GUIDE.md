## 1. 왜 제작 과정과 코드를 함께 공개하는가

교회 홈페이지를 새로 만들려고 하면 외주 제작비 수백만 원과 매달 빠져나가는 관리비가 부담스럽고 직접 무료 빌더를 쓰자니 주보 한글 파일이나 설교 아카이브 관리가 답답할 때가 많습니다. 반대로 `AI`에게 막연히 "교회 홈페이지 만들어 줘"라고만 요청하면 겉모습만 그럴듯하고 실제 주일 행정에는 쓰기 어려운 시제품이 나오거나 존재하지도 않는 교회 연혁과 가짜 게시글이 섞여 들어가는 시행착오를 겪게 됩니다.

일광교회 (https://ilkwang.org)는 구 홈페이지 노후화 문제를 해결하면서 **도메인 연장비 외 월 고정비 `0원`**으로 직접 운영할 수 있는 홈페이지를 `AI` 에이전트와 함께 구축했습니다. 다른 교회 목회자분들과 사역자분들이 똑같은 시행착오를 반복하지 않고 이 저장소를 `AI`에게 참고본으로 건네어 각 교회 형편에 맞는 홈페이지를 빠르게 세우실 수 있도록 실제 제작 전 과정과 검증 기준을 기록으로 남깁니다.

## 2. 월 고정비 0원 기술 구성과 역할 분담

전문 개발자가 상주하지 않는 교회일수록 구조가 단순하고 무료 한도가 넉넉하며 인수인계가 쉬워야 합니다.

| 구성 요소 | 채택 기술 | 교회 운영상 역할 | 월 고정 비용 |
|---|---|---|---|
| **웹 화면 및 관리자** | `Next.js 16` (`App Router`, `TypeScript`, `Tailwind CSS`) | 성도용 홈페이지 화면과 `/admin` 21개 사역 관리 화면 제공 | `0원` |
| **데이터베이스 및 파일 저장소** | `Supabase` (`Free` 요금제) | 게시글, 주보, 설교 목록 (`500 MB` 한도) 및 사진, 동영상, 첨부 문서 (`1 GB` 한도) 보관 | `0원` |
| **웹 서버 배포** | `Vercel` (`Hobby` 요금제) | 인터넷 접속 처리, `HTTPS` 보안 인증서 자동 발급, 관리자 비밀번호 환경변수 보관 | `0원` |
| **교회 공식 도메인** | 기존 등록기관 유지 (`ilkwang.org`) | 교회 고유 인터넷 주소 연결 | 연 `23,100원` 수준 |

특히 `src/lib/cloud-store.ts`를 **이중 저장 구조**로 설계하여 `Supabase`를 연결하기 전에는 내 컴퓨터의 `data/*.json` 파일만으로 전체 사이트와 관리자 모드가 그대로 작동합니다. 덕분에 다른 교회에서 처음 시작할 때도 복잡한 클라우드 가입 없이 내 컴퓨터에서 먼저 디자인과 게시판을 완성한 뒤 마지막에 인터넷으로 배포할 수 있습니다.

## 3. 실제 제작 6단계 과정과 시행착오 해결 기록

### 1단계. 초기 AI 시제품의 함정 발견과 1차 사료 원칙 확립

처음에는 `AI`가 빠르게 만들어 놓은 시제품 화면에서 출발했으나 꼼꼼히 대조해 보니 큰 함정이 있었습니다. `AI`가 빈칸을 채우려고 존재하지 않는 연혁 연도, 가짜 은행 계좌번호, 임의로 지어낸 교회 소식 4건과 부서 소개 문구를 그럴듯하게 넣어 둔 것이었습니다.

- **해결 방법**: 구 홈페이지 공지글, 실제 주보 파일, 교회 유튜브 영상 목록처럼 **확인 가능한 1차 자료**에 근거가 없는 게시글과 연혁 문구는 전수 조사하여 모두 삭제하거나 실제 주보 기록에 맞춰 고쳤습니다. 교회 홈페이지를 `AI`와 만들 때는 반드시 "모르는 내용은 지어내지 말고 비워 두라"는 지침을 첫 줄에 주어야 합니다.

### 2단계. 교회 고유 분위기 복원과 관리자 화면 통일

새 홈페이지로 바꾸더라도 기존 성도님들에게 익숙한 본당 사진, 네이비 (`#1a2744`)와 포레스트 그린 (`#2E7D32`) 배색, 마우스로 돌려 볼 수 있는 3D 회전 사진 큐브 (`src/components/HeroPhotoCube.tsx`)는 그대로 살렸습니다. 동시에 실제 운영하는 교역자 입장에서 불편했던 관리자 화면을 여러 차례 다듬었습니다.

- **게시글 작성 방식 통일**: 어떤 게시판은 버튼을 누르면 빈 항목이 바로 생기고 어떤 게시판은 작성 창이 열리는 불일치를 없애고 모든 게시판에서 제목과 본문 입력 칸을 먼저 보여 주도록 통일했습니다.
- **불필요한 요소 제거**: 관리자 계정 하나로 운영하는 현실에 맞춰 게시글 작성자 입력 칸을 없애고 설교 아카이브 옆의 게시글 개수 표기나 불필요한 기능 설명 문구를 덜어냈습니다.
- **최상단 한 줄 알림바 개선**: 줄바꿈 기호로 구분하던 방식을 한 줄에 입력 상자 하나씩 추가하고 지우는 직관적인 구조로 바꿨습니다.

### 3단계. 한국 교회 주보 한글 파일 (`.hwp`, `.hwpx`) 자동 추출기 개발

한국 교회 행정에서 가장 시간이 많이 드는 일은 매주 한글 프로그램으로 만든 주보를 홈페이지에 다시 옮겨 적는 작업입니다. 이를 자동화하려고 `src/lib/hwp-parser.ts`를 직접 구현하고 실제 주보 수십 호를 넣으며 정교하게 보완했습니다.

- **구형 `.hwp`와 신형 `.hwpx` 동시 지원**: 구형 한글 파일은 `OLE2` 복합 문서 안의 `PrvText` 텍스트 스트림을 해독하고 신형 `.hwpx` 파일은 압축된 `XML` 문단과 표 (`<hp:tbl>`) 구조를 직접 읽어 들입니다.
- **표 순서 역전 버그 해결**: 2026년 하반기 주보 16호에서 교회 일정이 엉뚱하게 `축하합니다` 결혼 소식 칸으로 들어가는 현상을 발견했습니다. 원인을 추적해 보니 한글 문서 안에서 교회 일정 표가 제목 문단보다 `XML` 순서상 먼저 묶여 있었고 `7월 3-4일`처럼 시작일에 `일` 자가 생략된 날짜 표기가 섞여 있었습니다. 표 탐색 방향을 양방향으로 넓히고 날짜 판별식을 보강해 47호 전체가 한 글자 누락 없이 추출되도록 고쳤습니다.
- **소식과 일정 입력 칸 분리**: 관리자 화면 (`src/components/AdminBulletinStudio.tsx`)과 성도 열람 화면 (`src/components/BulletinBoardClient.tsx`) 모두에서 **교회 소식**과 **교회 일정** 상자를 깔끔하게 분리하고 여러 주보 파일을 한 번에 올리는 일괄 등록 기능을 더했습니다.

### 4단계. 구 홈페이지 역사 복원 — 2013~2019년 주보와 설교 850편

주보는 교회의 역사이므로 구 홈페이지 (`ilkwang.or.kr`)에 남아 있던 과거 자료를 빠짐없이 옮겨 담았습니다.

- **역대 주보 274호 통합**: 2013년 한글 주보 16건은 파서로 추출하고 2013~2019년 종이 스캔 이미지 주보 213건 (`429`쪽)은 시각 판독 워크플로로 본문을 복원한 뒤 성도들이 `원본 스캔 주보 보기`를 눌러 옛 주보 이미지까지 그대로 볼 수 있게 연결했습니다.
- **교차 검증으로 과거 오타 교정**: 복원한 주보 229건을 설교 아카이브 850편 및 성도 명단과 대조하여 과거 업로드 당시 전주 주보가 잘못 중복 첨부된 2건과 날짜 및 권호가 잘못 적힌 6건을 찾아 바로잡았습니다.
- **옛 앨범 77개 복원**: 과거 행사 사진들을 촬영 및 게시 연도에 맞춰 이관하고 `예배와 절기`, `성례와 임직`, `전도와 선교`, `다음세대`, `수련회와 탐방`, `교제와 봉사`, `교회 역사` 7개 표준 태그로 정리했습니다.

### 5단계. 아이폰 현장 업로드 오류 해결과 봉사자 계정 및 용량 관리

실제 스마트폰으로 시험해 보면서 발견한 현장 문제들을 하나씩 해결했습니다.

- **아이폰 사진 및 동영상 업로드 해결**: 아이폰 `Safari`에서 사진을 올릴 때 `The string did not match the expected pattern.` 오류가 발생하고 대용량 영상이 막히는 문제가 있었습니다. 서버 함수의 `4.5 MB` 전송 한계에 걸려 일반 텍스트 오류가 반환되면서 생긴 현상이었습니다. 브라우저에서 `.heic` 사진을 자동 변환 및 압축하고 (`src/lib/client-upload.ts`) `Supabase` 서명 주소 (`src/app/api/upload/presign/route.ts`)로 최대 `50 MB`까지 직접 전송하도록 바꾸어 해결했습니다.
- **사진 봉사자 전용 계정 분리**: 전체 설정을 다루는 `사이트 관리자 모드` (`admin`) 외에 앨범 업로드 화면만 열리는 `사진 업로드 전용` (`photo`) 계정을 나누어 미디어 봉사자에게 안심하고 비밀번호를 공유할 수 있게 했습니다.
- **버튼 옆 즉시 저장 확인과 상단 용량 표시줄**: 글이나 앨범이 길어지면 화면 맨 위에만 뜨는 알림을 놓치기 쉬워서 마지막으로 누른 저장 버튼 바로 아래에 초록색 확인 문구가 뜨도록 개선하고 (`src/components/ActionFeedbackBubble.tsx`) 관리자 상단에 데이터베이스와 파일 저장소 현재 사용량을 막대그래프로 상시 표시했습니다 (`src/components/AdminUsageMeter.tsx`).

### 6단계. 담임목사님 인쇄본 감수와 대중교통 실측 검증

- **시니어 담임목사님을 위한 A4 확인 요청서**: 60대 담임목사님께 컴퓨터 화면을 일일이 열어 보시게 하는 대신 꼭 결정하셔야 할 항목 (설립 연혁 세부 사항, 헌금 계좌 숫자, 인사말과 약력, 비전, 주보 성도 실명 공개 범위)만 `14pt` 큰 글씨와 체크박스로 구성한 A4 인쇄용 `PDF` 문서로 만들어 보고드렸습니다.
- **대중교통 정보 직접 대조**: 구 홈페이지와 초기 시제품의 버스 번호가 서로 달라 실제 지도 정류장 정보 (도보 2~4분 내 정류장 4곳, 정류장 번호 `08123`, `08124`, `08336`, `08546`)를 하나씩 확인해 실제로 정차하는 간선, 지선, 마을버스 번호만 정확히 남겼습니다.

## 4. 다른 교회에서 AI로 우리 교회 홈페이지 만드는 5단계 절차

### 1단계. 시작 전 우리 교회 기초 자료 6가지 모으기

`AI`에게 작업을 시키기 전에 아래 자료를 폴더 하나에 모아 두면 가짜 샘플 데이터가 생기는 일을 예방할 수 있습니다.

1. 교회 공식 명칭, 소속 교단과 노회, 도로명 주소, 대표 전화번호, 이메일
2. 주일 예배 및 주중 기도회 정확한 시간과 장소
3. 담임목사님 인사말, 약력, 섬기는 교역자 명단과 증명사진
4. 최근 주보 한글 파일 (`.hwp` 또는 `.hwpx`) 2~3개 (자동 추출 시험용)
5. 교회 유튜브 채널 주소 (예: `https://www.youtube.com/@채널아이디`)
6. 교회 로고 이미지 (`PNG` 또는 `SVG`)와 본당 대표 사진 2~3장

### 2단계. 이 저장소 내려받기 및 로컬 실행 확인

터미널에서 아래 명령어를 실행해 내 컴퓨터에서 먼저 샘플 사이트가 열리는지 확인합니다.

```bash
git clone https://github.com/zooneng/ilkwang-church-web.git our-church-web
cd our-church-web
npm install
npm run dev
```

### 3단계. AI 코딩 도구에 맞춤 개편 요청하기

`Claude Code`, `Cursor`, `Antigravity`, `Codex` 등에서 `our-church-web` 폴더를 열고 아래와 같이 요청합니다. 루트에 있는 `AGENTS.md`의 5단계 개편 점검표를 `AI`가 자동으로 읽고 순서대로 작업합니다.

```text
AGENTS.md와 docs/BUILD-PROCESS-AND-AI-GUIDE.md를 먼저 읽어 주세요.
이 레퍼런스 홈페이지를 바탕으로 우리 교회([교회 이름]) 홈페이지를 만들려고 합니다.

[우리 교회 확정 정보]
- 교회명 및 교단: ...
- 주소 및 연락처: ...
- 예배 시간표: ...
- 섬기는 사람들: ...
- 유튜브 채널: ...

[작업 지침]
1. 알려 드리지 않은 연혁, 부서 장소, 헌금 계좌, 게시글은 절대 임의로 지어내지 말고 비워 두거나 저에게 물어봐 주세요.
2. public/ 폴더의 일광교회 로고와 배경 사진을 제가 드리는 파일로 교체하고, 사이트 전체에 '일광교회' 문구가 남아 있지 않은지 검사해 주세요.
3. 첨부한 우리 교회 주보 파일이 /admin?tab=bulletin에서 예배 순서와 소식, 일정으로 잘 나뉘어 읽히는지 확인하고 우리 주보 양식에 맞게 src/lib/hwp-parser.ts를 조정해 주세요.
```

### 4단계. Supabase 무료 데이터베이스와 Vercel 무료 서버 연결

1. **교회 공용 구글 계정**을 하나 준비해 `GitHub`와 `Vercel`에 가입하고 그 `GitHub` 계정으로 `Supabase`에 로그인합니다.
2. `Supabase`에서 무료 프로젝트를 만든 뒤 `SQL Editor` 창에 `supabase/schema.sql` 파일 내용을 그대로 붙여넣고 `Run`을 누르면 데이터베이스 테이블, 보안 규칙 (`RLS`), 파일 저장소 (`church-uploads`), 용량 확인 함수가 한 번에 만들어집니다.
3. 수정한 코드를 교회 `GitHub` 저장소에 올리고 `Vercel`에서 해당 저장소를 연결한 뒤 `.env.example`에 적힌 환경변수 (`ADMIN_PASSWORD`, `PHOTO_ADMIN_PASSWORD`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`)를 입력하고 배포 (`Deploy`)합니다.

### 5단계. 담임목사님 최종 감수 및 도메인 연결

배포된 임시 주소로 접속해 스마트폰과 PC에서 사진 업로드, 주보 등록, 설교 동기화를 시험한 뒤 담임목사님께 인쇄본이나 화면으로 최종 확인을 받고 교회 도메인을 `Vercel` 프로젝트의 `Domains` 메뉴에 연결하면 완료됩니다.

## 5. 목회자와 사역자를 위한 4가지 보안 및 개인정보 수칙

1. **주보 속 성도 실명과 사진 공개 범위 확인**: 주보의 생일, 결혼, 장례, 심방, 새가족 명단과 교회학교 어린이 사진은 인터넷 전체에 공개할지 당회와 담임목사님 방침을 먼저 확인하십시오. 공개 저장소 (`GitHub`)에는 실제 성도 명단이 담긴 `data/*.json`이나 성도 사진 폴더를 올리지 않도록 `.gitignore` 설정을 유지해야 합니다.
2. **가짜 샘플 게시글 전수 삭제**: 개편을 마친 뒤 배포하기 전에 모든 메뉴를 한 번씩 열어 초기 예시 계좌번호 (`000000-00-000000`)나 예시 문구가 남아 있지 않은지 반드시 점검하십시오.
3. **비밀번호는 코드에 적지 말고 환경변수에 등록**: 관리자 비밀번호나 `Supabase` 비밀 키를 소스 코드 파일 안에 직접 적으면 외부에 노출됩니다. 반드시 `.env.local`과 `Vercel` 환경변수 설정창에만 입력하십시오.
4. **분기별 백업 파일 보관**: 클라우드 장애나 실수에 대비해 분기마다 한 번씩 `/admin?tab=backup` 메뉴에서 전체 데이터 백업 파일을 내려받아 교회 행정 컴퓨터에 보관해 두십시오.
